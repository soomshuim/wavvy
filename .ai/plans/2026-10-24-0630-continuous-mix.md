# 06:30 최종 20곡 연속 믹스

## 요청과 범위

- 추가 젠 원문: “유튜브에서는 2번 반복해야하는 점을 잊으면 안돼.” 기존 `MASTER/cli/SPEC.md`의2회 반복 필수와 같다. 1회 기준 음원을 보존하고, 유튜브용은 20곡 번호순을 총 2회 반복한 별도 M4A로 만든다. 1회 WAV는 보존하며, 공간 제약에 따라 2회 대용량 WAV는 만들지 않았다. 첫회20번→둘째회1번도 실제 박자를 맞춘 연결을 넣으며 단순 파일 concat으로 끝/처음 무음을 만들지 않는다. 별도 `scripts/continuous_mix_0630_repeat.py`와 `production/continuous-mix-20261024-repeat2.json`에 설정을 분리해1회 근거 해시를 보존한다. 전체 영상/업로드는 여전히 이 작업 범위에 없다.

- 젠 원문: “일단 업로드 안되면 여기까지만 하자. 이제 할 일은 20곡을 리믹스 형태로 끊어짐 없이 하나로 잇는거야. 반드시 박자가 곡에서 곡으로 넘어갈 때 이어져야해.”
- Suno 업로드는 기존 18곡 수락·6/11 미수락 상태에서 사용자가 중지했다. 추가 업로드·이름 변경·삭제·재생성은 하지 않는다.
- `input/download-manifest.json`에 연결된 현재 `input/tracks/`의 최종 20곡을 현재 번호 순서로 잇는다. 업로드용 175 목표 사본은 이 입력을 대체하지 않는다.
- 입력 20개를 덮어쓰지 않는다. 새 연속 믹스와 전환 청취 사본은 별도로 만든다. Downloads의 최종 청취 사본 20개는 입력 의존성이 아니며 사용자가 지워도 된다.
- 사용자가 연속 음원 제작을 명시 요청했으므로 이 범위의 긴 오디오 처리를 진행한다. 영상·YouTube 발매나 새 제목 결정은 범위에 없다.

## 확인한 선례와 제약

- 선례: `MASTER/cli/SPEC.md`의 `pack`은 음량 정리와 순차 `acrossfade`(앞뒤 곡 소리를 겹쳐 잇기)를 사용한다. 기본 0.8초 겹침과 반복 설정은 박자·마디 일치를 검사하지 않으므로 이번 요구의 완료 근거가 되지 않는다. 기존 기본 동작을 무관하게 바꾸지 않는다.
- `MASTER/SSOT.md`·`MASTER/ai/RUNTIME_RULES.md`·시리즈 concept와 실제 최종 목록을 기준으로 한다. No Pydub, FFmpeg 처리, 작은 실험 후 전체 제작, 처리 전 예상 길이와 제작 후 실제 길이를 대조한다.
- 실제 입력 20개는 기준 해시와 전부 일치한다. 48 kHz·2채널·float32, 총 4134.925186초, 1,587,813,044바이트다. 사전 가용 공간은 12,963,971,072바이트다.
- 8/13/18은 173 BPM 처리 목표, 다른 처리 15곡은 176 목표, 5/20은 승인한 원속도다. 목표값을 실제 모든 순간의 BPM(분당 박자 수)으로 단정하지 않는다.
- 설치된 FFmpeg 8.0.1에 atempo/asendcmd/acrossfade가 있다. rubberband 필터·실행파일은 없다. 기존 BPM 분석 환경과 코드를 먼저 재사용한다.
- 실행 워커는 `continuous_mix_0630`의 Sol 6.1/xhigh다. 컨트롤러 실제 환경의 Sol 6.1/xhigh override를 숨기지 않는다. 정식 결과 검토는 격리 Astra/high 1개로 한다.

## 진행 순서

1. 입력 20개 출처·순서·길이·해시를 고정하고, 앞뒤의 실제 타격·박자 간격·강박을 분석한다. 불확실한 구간은 표시하고 근거 없이 통과시키지 않는다.
2. 곡 몸통의 승인 속도를 살리며 전환부의 속도·박자·마디를 맞추는 작은 실험을 한다. 특히 176/173 목표 곡이 만나는 경계와 원속도 5/20 주변을 우선 확인한다. 전환 길이는 실제 음악의 마디를 기준으로 정한다.
3. 실험의 실제 출력에서 타격 정렬·박자 간격·소리 끊김·음량·길이를 확인한 뒤 19개 전환 계획을 확정한다. 필요한 새 처리 도구는 이번 시리즈의 재현에 필요한 범위로 한정한다.
4. 전체 연속 음원과 19개 전환 청취 사본, 실제 시작 시각·사용 구간·속도 처리·출처를 담은 목록을 만든다. 불필요한 임시 중복 대용량 출력을 피한다.
5. 전체 파일의 해독 가능 여부·예상/실제 길이·내부 무음·클리핑과 19개 전환의 실제 타격 정렬을 확인한다. 입력 20개 해시 불변을 다시 확인한다. 수치 검사가 자연스러운 청감이나 사용자 승인을 대신한다고 쓰지 않는다.
6. 원본 요구·대상 파일·원시 출력으로 격리 검토를 1회 수행한다. 검토 후 concept·SESSION·HANDOFF·CHANGELOG에 실제 산출물과 한계를 기록하고 커밋·푸시한다.

## 보존한 실패·결정 이력

- 초기 5ms 반복 tempo 명령은 합성 대조에서도 누적 오차가 재현돼 채택하지 않았다. 정적 1마디 처리와 실제 파형 위치 교정으로 전환했다. 3시범 수정 뒤 초기 19개 전환을 만들고 초기 15곳과 이웃 마디 대체 2곳의 기술 근거를 확보했다. 실패 원시와 제한된 대체 비교는 `work/0630-continuous-mix-20261024/`·`work/0630-atempo-timing-probe-20261024/`에 보존했다.
- 9→10은 공유 한 박 p90 18.425ms·마디 후보 p90 8.225ms이나 단발 파형 대응 31.582ms가 반복 기타 때문에 모호했다. 10→11은 마디 후보 차이 0ms이나 공유 한 박 p90 24.942ms가 내부 20ms 기준을 넘었다. 제한된 비교 뒤 자동 반복을 멈추고 실제 두 파일을 제시했다. 젠의 “둘 다 이대로 사용” 뒤 정확 파일 해시를 고정해 전체 제작을 진행했다. 이 승인은 자동 검사 통과나 전체 믹스 청취 승인으로 바꾸지 않는다.
- 초기 예상 3847.795072초와 대체 반영 전 계획 3794.466292초는 과거 계획값이다. 완성 1회 WAV의 실제 3790.339645833초가 현재 기준이다. 24-bit WAV의 SciPy mmap(큰 파일 일부만 직접 읽는 방법) 미지원은 읽기 호환 문제였으며, 3바이트 PCM 조각 읽기로 바꾸고 9,686,933 samples의 SciPy 전체 읽기 일치를 확인한 뒤 새 조각에서 진행했다. 실패 조각·원시를 보존했으며 오디오 손상으로 기록하지 않는다.
- 초기 전환·컨트롤러 원시는 `../validation/2026-10-24-0630-continuous-mix-worker-check.json`·`../validation/2026-10-24-0630-continuous-mix-controller-check.json`에 있다. 당시 전체 미착수·사용자 결정 대기는 현재 완료 결과로 대체된 이력이다.

재현 경로는 `scripts/continuous_mix_0630.py`, `scripts/continuous_mix_0630_repeat.py`, `SERIES/06-30/production/continuous-mix-20261024.json`, `SERIES/06-30/production/continuous-mix-20261024-repeat2.json`이다. 오디오 실행 워커의 파일은 완료 뒤 고정했으며 문서 마감에서는 변경하지 않는다.

## 기술 선례와 근거

- [Mixxx2.5 공식 설명](https://manual.mixxx.org/2.5/en/chapters/djing_with_mixxx): 실제 tempo와 박자 위치를 함께 맞추고, 곡 앞뒤의 유효한 음악 구간을 선택한다. 자동 검출은 틀릴 수 있으므로 출력 근거를 대조한다.
- [FFmpeg 공식 필터 문서](https://ffmpeg.org/ffmpeg-filters.html#atempo): tempo 변경 기능 자체와 실제 타격 위치 정확도는 구분한다. 동적 반복 명령의 문제는 설치된8.0.1의 합성 대조와 해당 버전 소스로 확인했다.
- [Beat This! 공식 구현](https://github.com/CPJKU/beat_this): 기존 설치된 torch 환경을 재사용한 작업 전용 환경에서 박·강박 보조 추정만 사용한다. 모델20ms 시간 격자와 half-time(실제 박을 두 박씩 묶어 읽는 경우) 한계는 실제 대역 타격과 대조한다.
- 원시 진단은 `work/0630-atempo-timing-probe-20261024/REPORT.md`, 실제 시범은 `work/0630-continuous-mix-20261024/prototype-results-v2b.json`·`prototype-v2b-waveform-validation.json`에 있다. 이 자료를 최종 믹스 검사와 혼동하지 않는다.
